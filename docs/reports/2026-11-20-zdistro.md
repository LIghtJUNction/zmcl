## 界面与安装体验

Settings 的 Launcher 卡片现在把版本、平台、程序位置和安装来源放在一起。来源信息来自与当前版本匹配的分发标记或安装回执；无效标记显示为未知来源，只有普通安装回执时也不会被标成 zdistro 包。识别来源后，界面给出相应的便携安装或包管理器更新提示。

[Debian 安装后的 Settings（历史附件）](https://drive.google.com/file/d/1jMOYzLeo1prfhObfF_XA1OE852OJKUNt/view)

检查更新由用户明确点击触发。程序通过现有任务子进程访问固定的官方 GitHub API，限制为最新十个发行、1 MiB 响应和二十秒网络时限；子进程完成后退出。版本比较遵循 SemVer，并检查当前系统和架构是否有对应资产。界面覆盖更新可用、已是最新、当前构建更高、平台包缺失、离线、损坏响应和重试；发行链接可以打开或复制。浏览器 helper 退出失败时会显示明确的复制链接提示。

安装完成后的文字说明现在包含实际版本、目标目录、完整启动命令和同目录升级命令。若 PATH 选择了另一份 zmcl，安装器会同时显示两份路径，帮助用户启动刚安装的副本。Windows 的安装目标改为 `bin/zmcl.exe`，并保留旧受管布局的兼容处理。

安装器以路径和摘要识别受管文件。标准 zdistro 便携安装管理程序、图标、桌面入口、分发标记及安装回执这五项文件；清单本身独立保存。更新拒绝覆盖已修改或不属于该安装的文件，卸载保留用户修改过的文件和非受管数据。实际验收在含空格的前缀内外放置了合成游戏数据，并确认卸载后仍完整存在。

## 分发方式与可复核性

zdistro 负责把经确认的程序及资源组织为各平台软件包。zmcl 的 wrapper 负责固定工具版本、核对源码和程序身份、指定必须生成的格式，并复核生成内容。兼容性取决于程序实际调用的系统库，因此 Linux 包记录 ELF 依赖和 ABI 下限，Windows 包在原生 Windows 上独立构建和启动窗口。

本轮固定使用 zdistro 0.1.0，源码提交为 `6a54a137fc697d372b54ef85105315f2ce522b3d`，zipapp 摘要为 `a30a4580254a6510c2019e3e7a684c31d4e435b69f32f33d3813ef6264544908`。流程依次执行 doctor、plan、build、verify、matrix；缺失、重复或跳过请求格式都会失败。原始 manifest 和 receipt 保持字节不变，真实安装、窗口和发布结果单独记录。

固定版本的 zipapp 有一个已复现的退出码问题：某些校验失败会输出错误却退出 0。wrapper 同时核对结构化结果、完整目标集合和摘要，防止只靠退出码判定成功。[边界回归](../validation/zdistro-packaging-boundaries-2026-11-20.json)与[退出码复现](../validation/zdistro-0.1.0-exit-code-2026-11-20.json)保存了这一事实；未修改上游 zipapp 来隐藏它。

### Linux 安装、升级与界面

DEB 在固定镜像的 Debian forky/sid 用户空间中通过 apt 实际安装。验收先从正式 0.1.3 的源码与二进制生成一个私有旧版 DEB 夹具，创建合成实例和存档，再升级到 0.1.4。新程序可以读取旧实例；升级、重装、卸载均保留数据。旧版夹具不属于公开的 0.1.3 发行资产。

已安装的 `/usr/bin/zmcl` 还通过严格文件检查、桌面入口检查、动态库解析，以及九组 X11 更新界面场景。场景使用隔离的 curl/browser 响应夹具，覆盖 1120×760 与 800×600 窗口，共产生十一张截图；其中 0.1.5 是“存在新版本”的场景数据。自动检查与人工视觉审阅分别留有记录。十一张图的主要卡片和按钮没有观察到意外裁切或重叠；离线与损坏响应场景的底部单行摘要使用省略号，完整错误仍在上方更新卡片可读，这一非阻塞观察保留在独立审查记录中。

Linux 便携路径使用公开的旧版 0.1.3 tar 先安装，再用新 tar 在同一含空格目录升级。验收核对两次安装的真实程序摘要、原始 release.json、五项受管文件、分发标记和安装回执；另外创建 PATH 指向系统另一份 zmcl 的情况，检查启动和升级提示。卸载后合成数据保持不变。

首次完整 DEB 验收发现测试镜像默认排除 `/usr/share/doc/*`，因此 dpkg 报告文档缺失。后续只为私有验收安装增加本应用文档的显式保留选项，继续要求完整文件检查通过；镜像默认策略、生产 DEB 和原失败记录均保留。原始精简镜像中的独立验收则使用普通 `apt --no-install-recommends`，没有这些文档选项。

精简镜像最初既没有已安装的 CA 证书包，也没有系统信任文件。DEB 的显式依赖真实安装了证书，随后官方 Releases 页面 HTTPS 返回 200，TLS 校验结果为 0。一次真实的 `zmcl update check --json` 成功返回当前 0.1.4 高于当时已公开 0.1.3 的状态，程序摘要未改变；没有使用响应夹具或自定义 CA 环境。

### Windows 原生验收

[正式运行 44739704182](https://github.com/LIghtJUNction/zmcl/actions/runs/44739704182)使用固定 Rust 1.100.0、MSVC 目标和静态 CRT 选项，在 Windows 原生环境（build 26100）完成构建。直接 DLL 导入检查没有发现数字版本的 VCRUNTIME/MSVCP 依赖；Win32/OpenGL 系统库和外部 Python、curl、Java 仍是实际运行条件。

Windows ZIP 在实际系统中解包、校验、安装到含空格的私有目录，并运行已安装程序的版本命令。随后启动其自己的 Win32 窗口，截取 968×649 客户区图像，确认非空并正常自动退出；卸载删除五项未修改的受管文件，保留前缀内外两份合成游戏数据。

## 验收边界

Linux 预编译程序的直接依赖要求 glibc 2.39+、Fontconfig 2.17.0+、FreeType 和 X11/XWayland。此次 Debian 测试共享宿主内核，不能代替所有发行版与桌面组合的实机兼容性验证。用户级文件助手要求 Python 3.8+，打包端要求 Python 3.11+；本轮原生执行的解释器版本记录在各回执中，未额外声称 Python 3.8 实机覆盖。

Windows 本轮验证到原生构建、软件包、安装、窗口与卸载。真实账号登录、Minecraft 启动、驱动差异及全部 GUI 操作仍需对应的专项验收。macOS 本轮未提供应用安装包；已有框架探针记录保持其原范围。

本轮没有新增完整 GUI 内存基准，因此不宣称新的 RSS/PSS 降幅，也没有将历史助手进程优化改标为 0.1.4 整体收益。完整 GUI 低于 10 MiB 的目标仍未达成。所有软件包的签名状态保持为未签名。
