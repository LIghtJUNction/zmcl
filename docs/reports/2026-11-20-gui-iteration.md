# zmcl 0.1.2：GUI 功能、性能与跨平台验收

日期：2026-11-20（Asia/Taipei）。应用源码：[e86b584](https://github.com/LIghtJUNction/zmcl/commit/e86b5841532ef04cc74cea5585ae396150452408)。

本轮完成了创建和安装流程改进，减少无效重绘与不再需要的列表驻留，并把框架优化发布为 zgpui 0.1.5。**完整窗口的固定重绘工作负载中，CPU 时间中位数降低 44.53%；2,000 个合成世界的业务流程中，返回首页后的 GUI RSS 降低 14.52%、PSS＋SwapPss 降低 23.05%。** 这两组数字来自不同的固定候选和场景，不是最终发行版所有场景的保证。空首页常驻内存基本持平，操作过程的整树峰值没有稳定下降。

## 1. 可直接使用的功能改进

- 新建实例会异步获取官方发行版，支持筛选、滚动和精确版本优先匹配。自动建议不重复的名称，并考虑跨平台大小写碰撞。
- Vanilla、Fabric、Quilt、Forge、NeoForge 可以直接点选；Forge/NeoForge 保留明确的加载器版本输入。
- 默认“创建并安装”，也可“仅创建”。安装失败后保留实例，可以重试。
- 库页面明确显示安装或账号方面的下一步，未选账号时引导进入账号页。
- Activity 隐藏时继续读取和保存有界日志，但不再因每段后台输出重绘整个窗口。登录自动展开 Activity，设备码和链接保持实时可见。
- 离开管理页或切换管理子页时释放旧行字符串和向量容量。当前实例与已排队任务保留自己的参数；迟到列表受页面、子页和实例匹配检查保护。

本轮较早的功能候选已实际完成 **Minecraft 1.21.1 的版本选择、GUI 创建、下载和安装，并以显式离线测试身份打开游戏欢迎窗口**。后来的正式组合重新执行了创建与管理 fixture，没有将较早的游戏结果改标为最终二进制的新实测。没有新增真实 Microsoft 登录、世界游玩或服务器运行验收。

## 2. 为什么这些改动减少了工作

**测量文字与绘制文字分开。** 确定一段文字的宽度只需字体度量，不需要先分配位图或上传纹理。框架分别使用 FreeType、Windows GDI 和 macOS CoreText 的前进距离；真正绘制时才创建像素缓存，避免仅为测宽污染可见文字缓存。

**限制长文本截断的探测次数。** 原实现逐字符删减并反复测宽；新实现复用候选缓冲区，在 UTF-8 边界有界探测。最终候选仍经过实际宽度检查，极窄空间、无效宽度和非单调测量都有边界处理。

**连续区域连续填充。** 矩形内部按扫描线填充，圆角边缘保留原覆盖率计算。4,201 组像素对照包含分数坐标、透明度、裁剪和异常几何，差异像素为零。独立矩形微基准的约 13.38 倍仅代表那组局部绘制工作，不能解释为 GUI FPS 提升。

**屏幕内容没有变化，就不重画。** 隐藏 Activity 时仍消费有界消息，任务开始、结束、失败仍刷新，避免输出积压和无效绘制同时发生。

**不保留永远不会复用的数据。** 管理页面每次返回本来就重新查询，因此离页期间保留旧列表没有复用价值。对象释放不保证分配器立即归还物理页；下面的业务测量也显示，离页瞬间 RSS 并未明显下降。

## 3. 完整窗口重绘对照

[完整公开数据及适用边界](../measurements/2026-11-20-renderer-iteration.json)记录了三对交错运行。旧版与候选保持相同应用运行时代码，框架版本和二进制不同；测量源码保留可重建补丁。

条件为 Linux、私有 Xvfb、1120×760 空库首页；每轮暖机20秒，11个静置样本，6秒内发送360次 Expose，再观察恢复静置。**Expose 请求数不是实际帧率。** 3,863 个原始样本独立复算一致；该场景只观察到一个 zmcl 进程，所以主进程与应用树一致。显示服务另计，观察器不计入启动器。

| 指标 | 基线 | 优化候选 | 解释 |
| --- | ---: | ---: | --- |
| 重绘 CPU 时间中位数 | 2.65 s | 1.47 s | −44.53% |
| 三轮重绘 CPU | 2.65 / 2.64 / 2.69 s | 1.41 / 1.47 / 1.66 s | 每对都减少 |
| 静置 RSS 中位数 | 9,780 KiB | 9,792 KiB | 基本持平 |
| 静置 PSS 中位数 | 4,153 KiB | 5,062 KiB | 未下降 |
| 重绘 RSS 中位数 | 9,724 KiB | 9,792 KiB | +0.70% |
| 重绘 PSS＋SwapPss 中位数 | 4,913 KiB | 4,990 KiB | +1.57% |
| 重绘观测 RSS 峰值 | 13,168 KiB | 13,260 KiB | 已超过10 MiB |

候选第二轮发生 GUI 与 Xvfb 换页，数据保留 SwapPss；PSS＋SwapPss 是先逐样本相加，再统计。宿主起始 MemAvailable 为3,758,088–4,392,336 KiB，已使用 swap 为20,069,636–20,590,276 KiB，没有系统缓存清空、CPU隔离或持续宿主PSI记录。以上是这台共享机器的固定工作负载结果，不代表所有操作、设备或平台。

## 4. 2,000 个世界的大列表业务场景

[公开业务数据](../measurements/2026-11-20-large-library-iteration.json)记录了基线1、候选1、基线2、候选2四轮。每轮使用同一 fixture 的独立副本：2,000个有效Java NBT世界，各160个ASCII标题字符。CLI确认返回2,000/2,000，JSON为1,106,002字节，没有触及GUI的2 MiB输出上限。这些是合成元数据，不是游戏可加载性验收。

窗口固定1120×760。切页后等待GUI无子进程持续1.2秒，再静置2秒、采样3秒。下表为每轮中位数的组中位数，单位KiB；n=2时就是两个数的中点，没有计算置信区间。

| 阶段 | RSS：基线 → 候选 | PSS＋SwapPss：基线 → 候选 |
| --- | ---: | ---: |
| 初始 Library | 9,970 → 9,916 | 5,144.5 → 5,069 |
| 首次 Worlds | 12,756 → 10,948 | 7,894.5 → 6,111.5 |
| 返回 Library | **12,808 → 10,948** | **7,940 → 6,110** |
| 再次 Worlds | 15,140 → 13,342 | 10,313.75 → 8,534 |

返回 Library 的 GUI RSS 降低14.52%，PSS＋SwapPss降低23.05%；两对PSS＋SwapPss分别降低23.71%和22.38%。GUI的SwapPss全程观测为0。候选返回首页的RSS仍约10.69 MiB，**全状态低于10 MiB的目标未完成**。

计入单独采样的Xvfb后，返回Library的应用树＋显示服务PSS＋SwapPss为39,952 → 38,742.5 KiB，下降3.03%，不能把GUI的23.05%用于整个显示栈。

2,027个连续样本中，841个稳态样本全部完整，稳态应用树只有GUI进程。查询进出期间有28次进程退出窗口中的读取缺失，完整操作树不能给出完整中位数。两对整树PSS＋SwapPss观测峰值下界分别为42,357→41,939和35,101→48,679 KiB，方向不一致；Python峰值也没有稳定下降。观察器内存未测量，明确为null。

本任务暂停了编译，但其他宿主负载仍存在。36次快照中，load1为3.47–20.80，曾有5个cargo和1个rustc；CPU、内存、I/O PSI与系统换页均保留在数据中。两版从Worlds回Library后驻留量本身几乎不降，因此该结果证明的是**合并候选在这个流程中的稳态占用较低**，不能独立归因于某一处清理。

## 5. 跨平台实现和实际验收

| 层次 | Linux | Windows | macOS |
| --- | --- | --- | --- |
| zgpui 0.1.5 核心与原生窗口 | CPU/X11、OpenGL、像素和生命周期通过 | 实际Win32窗口、GDI/OpenGL 1.1字形及圆角通过 | 实际AppKit窗口、CoreText、arm64软件渲染探针通过 |
| zmcl 0.1.2 应用 | 构建、原生创建/管理及文件效果通过 | 正常GNU完整GUI构建与PE检查通过；原生应用运行待验收 | 应用本身构建与桌面流程待验收 |
| 本地托管服务器进程管理 | 仍依赖procfs/pidfd | 暂不支持托管start/stop | 暂不支持托管start/stop |

Python辅助入口统一探测实际Python 3.8+解释器，Windows考虑py启动器，支持字面路径ZMCL_PYTHON。探测有超时与有界输出，只缓存成功；脚本使用隔离UTF-8模式，不经过shell。实际本机脚本测试使用Python 3.14，3.8是支持边界检查，没有伪称本机运行过3.8。

Windows辅助进程统一抑制额外控制台，保留管道、日志和游戏进程组。框架修复默认资源标识符类型与固定长度标题缓冲区。正常Windows GNU构建没有临时UNICODE宏；最终PE仍是CUI子系统，没有把CLI整体改成GUI子系统。

以下是正式发布候选的真实框架像素输出，已人工检查。Windows为GDI Generic，macOS为Apple Software Renderer；不代表硬件GPU性能或整个启动器的Windows/macOS游戏流程。

## 7. 对结论的复核

- 功能有具体入口、输入和可观察文件效果；实现不自动等于所有OS或全部XMCL能力通过。
- 每个性能数字保留场景、完整二进制身份、单位、统计方法和未测量项。两组候选不改标为最终发行二进制的新测量。
- 矩形微基准、完整窗口CPU、GUI稳态内存、操作树峰值和显示服务分别说明。
- 原始采样保留在受控开发证据中；公开JSON去除私人路径、PID和原始会话日志。
- 后续仍需Windows/macOS完整应用与游戏流程、输入法/无障碍、原生Wayland，以及管理操作峰值和反复导航后的驻留剖析。
