## 用户可见的改进

实例克隆的暂存目录保持私有，失败或进行中的克隆不会进入正常实例列表。非法 Minecraft 版本修改会在写入前被拒绝，原实例配置保留。使用 `launch --wait` 时，启动器会保存游戏退出时间和退出码，便于后续判断上一次运行结果。对应代码和原始验收见 [生命周期修复报告](instance-lifecycle-fixes-20261120.zh-CN.md)。

安装器会先检查旧清单、文件归属及全部目标路径，再修改程序、图标、桌面入口和安装清单。已被用户修改的文件、未归属此安装的文件，以及不安全的目录或链接路径会使升级停止；已有文件保留。旧版本的清单格式继续可用。

提交文件前，安装器会为已有文件保存备份。可捕获的写入失败或 Ctrl-C 会恢复旧文件内容、权限与原清单；若恢复步骤本身也被打断，错误信息会指出待处理目标，旧备份继续保留。Linux 安装过程使用前缀目录上的系统锁，第二个安装进程会被拒绝，持有者退出后由系统释放。

卸载继续移除未修改的受管理文件，保留用户修改的文件及其清单。合成的实例、存档和无关文件在安装、升级、失败回滚及卸载中均保持原样。

## 可复跑命令

```sh
cargo fmt --all -- --check
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo build --locked
python3 -B scripts/test_lifecycle_cli.py target/debug/zmcl
python3 -B scripts/test_install.py
cargo build --release --locked
```

从新的源码或分发包执行原有安装命令即可走新的升级预检：

```sh
python3 scripts/install.py install --binary target/release/zmcl
```

遇到修改文件保护提示时，先检查提示列出的文件并保留所需自定义内容。安装器不会通过强制覆盖解决冲突。
