# zmcl 实例流程修复与验收

日期：2026-11-20。源码提交：[2041e8337b344e2cab5b8503e73b3655bcfc91f1](https://github.com/LIghtJUNction/zmcl/commit/2041e8337b344e2cab5b8503e73b3655bcfc91f1)。开发基线：`0a7dda0a582f00334a61a1c236cb9f50ca9a64ed`。

这批修复解决实例复制、配置修改和等待游戏退出时的三个状态问题。代码经过 Linux 本机测试，已推送到 `fix/instance-lifecycle-20261120`，交由正在维护 GUI、zgpui 接入和发行的现有负责人整合。

## 已修复的行为

| 场景 | 原因 | 修复后的行为 | 对应验证 |
| --- | --- | --- | --- |
| 克隆过程中读取实例列表 | 普通 `clone-*` 临时目录会被当作正式实例读取，复制尚未完成时没有有效配置。 | 新克隆使用隐藏的 `.clone-*` 暂存目录，完成后再发布目标实例；临时复制不会阻断列表。 | 测试覆盖暂存目录尚未写入和已写入配置两种状态；重新打开实例库后仍能读取原实例。正式损坏实例仍会明确报错。 |
| 修改 Minecraft 版本 | 创建实例会校验版本 ID，解析修改后的配置时缺少相同校验。 | 创建和配置解析使用同一校验；非法修改立即失败，原配置文件和已安装状态保持原样。 | 经真实命令解析入口测试空值、路径字符、控制字符、超长值；同时保留带空格的历史版本、快照、alpha/beta 和下划线格式。 |
| 使用 `launch --wait` 等待游戏结束 | 已取得子进程退出结果，但启动记录中没有保存退出事实。 | 确认退出后原子写入 `exited`、退出时间和退出码，保留 PID、开始时间和日志路径；非零退出同样保存记录并返回游戏错误。 | 受控 fake-Java 子进程分别以 0 和 7 退出，检查记录和后续实例操作保护；未等待的启动明确保持 `exited:false`。 |

修改文件为 `src/app.rs`、`src/instance_manage.rs`、`src/runtime.rs` 和 `src/main.rs`。其中 `main.rs` 只增加配置回归测试。

## 验证范围与后续工作

本次文件往返使用生成的 NBT 和明确标注的模拟 region 数据，没有启动 Minecraft、下载游戏或访问用户存档。启动状态测试运行了受控子进程。Windows/macOS 的退出保护契约另有模拟检查，原生平台运行仍需实测。

旧版可能遗留的普通 `clone-*` 目录保持原样，因为这个前缀也可能属于合法实例。未等待启动在 Windows/macOS 上的后台进程监护继续由后续跨平台工作补齐。

当前公开 AUR 包为 [`zmcl-bin 0.1.0-1`](https://aur.archlinux.org/packages/zmcl-bin)，本轮已直接读取 AUR Git 远端和 RPC 核实。该包仍对应此前发布的预览版本。GUI 功能扩展、统一 zgpui、低于 10 MiB 的内存目标和下一版发行由现有维护会话继续推进；这批修复没有新增内存测量结果。
