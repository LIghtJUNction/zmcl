Project Z / v0.1.2 · 开发预览

Minecraft 启动器

zmcl 是基于 Rust 与 Project Z 的原生启动器。提供 Java 版实例、加载器和内容管理，支持图形界面与命令行。

目前主要在 Linux 上开发和验证。功能覆盖与内存优化仍在进行中。

安装

Arch Linux

使用 AUR 包 zmcl-bin 安装官方预编译程序。

AUR
paru -S zmcl-bin

当前包为 0.1.2-1 开发预览，已完成公共新克隆构建、正常升级和安装后窗口验收。也可运行 yay -S zmcl-bin，用 zmcl --version 核对实际安装版本。

Linux x86_64

下载 v0.1.2 开发预览（tar.gz，679,358 字节）。此预编译包要求 glibc ≥ 2.39、Fontconfig ≥ 2.17.0、X11/XWayland 与 FreeType。默认使用 CPU 绘制，无需 OpenGL；Python ≥ 3.8 和 curl 在相应操作期间运行，Java 与 Minecraft 单独安装。

从源码构建

按仓库工具链安装 Rust。Linux 默认 CPU 后端需要 X11/XWayland、FreeType 与 Fontconfig 开发库。

Shell
git clone --recurse-submodules \
  https://github.com/LIghtJUNction/zmcl.git
cd zmcl
cargo build --release --locked
./target/release/zmcl gui

Windows 完整 GUI 交叉构建已通过；Windows 应用原生运行，以及 macOS 应用构建和桌面流程仍待验收。发行包仅提供 Linux x86_64。完整构建说明 ↗

开始使用

安装后，在应用菜单打开 zmcl，或运行 zmcl gui。创建实例时筛选 Minecraft 发行版、选择加载器，默认创建并安装；也可先选择仅创建。

也可以通过命令行创建实例。下面使用明确的单机身份：

示例 · Minecraft 1.21.1
zmcl instance create survival --version 1.21.1
zmcl install survival
zmcl launch survival --offline Player

Microsoft 设备授权流程已接入，但真实账号的登录、刷新和启动仍待完整验收。

当前功能

v0.1.2 完善了发行版筛选、自动建议实例名和创建安装流程。最终 Linux 程序通过四组创建与六项管理操作验收；实际游戏、加载器和联网流程保留各自原构建的记录。

游戏与加载器
Java 版安装、修复和启动。原版 26.3、Fabric / Quilt / Forge 1.21.1 已有此前构建的真实菜单记录；本版未重跑实际游戏，NeoForge 仍待实机验收。
实例
筛选官方发行版、建议不重复的名称，选择创建并安装或仅创建。保留配置、克隆、回收站和恢复，以及下载校验、缓存复用与损坏修复。
Modrinth
模组搜索与添加、mrpack 导入与导出。模组启停、更新、移除和恢复主要通过命令行完成。
世界与备份
GUI 已验收世界目录导入、ZIP 导出、备份与确认恢复，并保留恢复前快照。CLI 还提供克隆等操作；本轮使用合成存档，没有把文件往返等同于实际游戏内游玩。
资源与服务端
资源包、光影包及本地服务器已有 GUI 管理入口。本版验证了未托管资源文件保留、创建服务器及 EULA 未接受时拒绝启动；真实联网下载、光影渲染和开服仍待分别验收。
运行环境
下载并校验所需 Java。Horizon 官方启动器组件的下载、签名校验和版本运行已验证，完整游戏流程尚未验证。

资源占用

低于 10 MiB 的完整 GUI 内存目标仍未达到。下面分别列出当前发行包体积、两组预发行候选对照和历史测量。

v0.1.2 Linux 主程序为 1,473,144 bytes，下载包为 679,358 bytes；展开后 7 个常规文件共 1,526,666 bytes。应用源码为 e86b584，使用 zgpui 0.1.5。文件体积不含系统库、Java、游戏和缓存，也不等同于运行内存。

开发计划

功能对照固定在 XMCL v0.73.1，完整覆盖尚未完成。当前优先处理以下工作：

  1. 降低 GUI 内存。已接入 zgpui 0.1.5 的真实原生 CPU 后端；继续降低启动、重绘和按需 CLI / Python 的操作期开销，保持主进程与完整相关树的测量。
  2. 补齐图形界面。完善已有管理页面，接入更多仍只通过 CLI 提供的操作，并补足大存档、复杂整合包和真实服务端的窗口验收。
  3. 完善账号和内容来源。完成真实账号流程验收，再补齐 CurseForge、FTB、Packwiz 等来源及复杂整合包场景。
  4. 扩展平台与协作能力。Windows/macOS 应用原生运行验收、签名自更新、无障碍、P2P 联机和云备份仍在待办中。Bedrock 尚未支持。
